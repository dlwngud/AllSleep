# AllSleep UX 개편 실행안

이 문서는 현재 코드 검토를 바탕으로 한 제품·디자인·개발 작업 명세다. 이미지는 작업 완료 후의 제안 모습이며 현재 구현 상태가 아니다. 앱 이름은 확정되지 않았으므로 AllSleep을 유지했다. 실제 앱 코드는 변경하지 않았다.

## 공통 기준

- 무료 핵심: 한 기기의 수면 잠금, 기본 일정, 긴급 접근, 본인 기록 조회, 기본 목표와 요약. 기존 기록은 기간이 지나도 조회할 수 있도록 하고 유료는 분석·자동화에 가치를 둔다.
- 유료 추가: 여러 기기 동시 잠금, 복수 루틴과 고급 규칙, 장기 비교와 적용 가능한 개선 계획. 안정성·오류 복구·긴급 접근은 무료와 유료 모두 동일하게 보장한다.
- 기록의 기준은 수면 모드 시작·종료 시각이다. 실제 수면 시간, 수면 단계, 깊은 수면, 의료적 효율을 단정하지 않는다. 규칙 기반 안내를 AI 분석으로 소개하지 않는다.
- 네이비 배경, 보라색 주요 행동, 라벤더 보조 색상, 기존 왕관·수면안대 캐릭터를 유지한다. 카드의 광채와 애니메이션은 줄이고 본문 대비를 높인다.
- 주요 동작은 탭으로 실행할 수 있어야 한다. 최소 48dp 조작 영역, TalkBack 의미·순서, 큰 글꼴, 작은 화면, 가로 모드에서 확인한다.
- 작업은 각 단계가 이전 단계에 누적되는 방식이다. 단계 중 핵심 기능이 막히는 변경은 먼저 내보내지 않는다.
- 시안의 날짜와 기록 숫자는 예시다. 가격·체험·혜택·동기화 완료는 실제 데이터와 확인 결과로 표시한다.

## 0단계: 즉시 수정 — 상태와 결과를 믿을 수 있게 만들기

### 작업

1. Settings 오류의 확인·뒤로가기·닫기에서 오류 상태를 해제한다. 실패한 작업의 입력과 화면 위치는 보존한다. 재시도는 해당 작업만 다시 실행한다.
2. Home·Stats의 오류를 화면에서 드러낸다. 초기 조회 실패와 사용 중 새로고침 실패를 구분한다. 기존 데이터가 있으면 유지하고 오류 안내만 추가한다.
3. 잠금 상태를 준비 필요 / 준비 완료 / 시작 요청 / 실행 확인 / 실행 중 / 종료 요청 / 종료 확인 / 실패로 구분한다. 드래그 완료나 요청 전송을 성공으로 표현하지 않는다.
4. 시작 버튼은 처리 중 비활성화하고 짧은 상태 문구를 표시한다. 응답이 오래 걸리면 실행 여부를 다시 확인하고 재시도 경로를 제공한다. 확인되지 않은 작업을 실패나 성공으로 단정하지 않는다.
5. 취소는 시작 요청 전에 가능하며, 서비스 실행 후에는 명시적인 종료 동작으로 처리한다. 서비스 시작과 취소가 겹쳐 뒤늦게 잠기는 경쟁 상태를 방지한다.
6. 평일·주말 취침/기상 활성화 값을 별도로 저장·동기화·예약한다. 주말 기상 필드명 오타를 수정한다. 기존 저장 값 이관은 실제 데이터 영향을 확인한 후 진행한다.
7. 시간은 24시간제 또는 기기 설정에 따라 일관되게 표시한다. 현재 카드별로 고정된 AM/PM 표시는 제거한다. 실제 다음 이벤트와 날짜를 함께 보여준다.
8. 기기 제한 안내의 취소와 로그아웃을 분리한다. 기존 기기를 유지할지, 이 기기로 교체할지, 다중 기기를 사용할지 명시적으로 선택하게 한다. 취소 후 기존 세션·미등록 상태를 정확히 유지하며 등록된 것처럼 표시하지 않는다.
9. 버전 정보·문의 메일 버전은 빌드 값에서 가져온다. 재시도 가능한 구독 오류는 복원과 닫기를 제공한다. 결제 취소를 오류로 취급하지 않는다.
10. 시작 시 알림 권한을 즉시 요청하는 동작을 제거하고 현재 관련 기능의 권한 설명으로 이동한다. 광고 때문에 잠금·긴급 접근·기상 확인이 지연되지 않도록 우선 경로를 제외한다.

### 완료 조건

- 모든 오류 안내가 닫히며 닫은 뒤 이전 화면을 계속 사용할 수 있다.
- 서비스가 시작되지 않으면 실행 중이나 활성화됨을 표시하지 않는다.
- 수면 시작 요청 반복·취소·재시도 시 중복 실행이나 뒤늦은 시작이 없다.
- 평일·주말 각각 취침/기상 ON/OFF 조합을 검증하고 실제 예약 결과와 UI가 일치한다.
- 기기 제한 안내 취소가 로그아웃을 발생시키지 않는다.
- 네트워크 실패·권한 철회·서비스 시작 실패·앱 복귀 시 결과가 명확하다.

## 1단계: 1차 개편 — 무료 첫 사용 완성

### 작업

1. 문제 공감과 해결 소개를 하나의 가치 소개 화면으로 합친다. 이후 시간 설정과 홈 진입으로 이어지게 한다. 진행 표시에는 실제 남은 단계만 표시한다.
2. 기본 수면 잠금과 기록은 비로그인 상태에서도 사용할 수 있도록 로컬 사용자·설정·실행·기록 구조를 마련한다. 화면만 건너뛰는 게스트 구현은 피한다.
3. 로그인은 백업·동기화 등 사용자가 계정의 이유를 이해하는 시점에 제안한다. 로그인 실패 후에도 로컬 핵심 기능을 유지한다.
4. 게스트가 로그인하면 기기 기록을 계정 기록과 병합한다. 중복 제거, 실패 시 보존, 다른 계정 전환 시 기록 소유권을 정의한다.
5. 권한 설정을 수면 잠금 준비 화면 하나로 통합한다. 권한별로 이유, 영향 기능, 설정 상태, 복귀 후 확인 결과를 표시한다.
6. 필수/권장/기능별 필요를 분리한다. 권한이 없으면 실제 영향을 받는 동작을 제한하고 시간 설정·기록·탐색은 제공한다. 알림 권한을 알림 차단 기능으로 설명하지 않는다.
7. 설정 복귀 후 체크리스트만 갱신하고 사용자가 의도하지 않은 잠금 시작을 자동 실행하지 않는다. 실행 의도를 이어갈 때는 상태를 확인하고 동작을 명확히 알린다.
8. 무료 통계 전면 블러를 제거한다. 본인 기록 목록, 기본 유지 시간, 최근 7일 요약, 기본 목표 달성을 공개한다.
9. 기록 없음 / 아직 조회 중 / 조회 실패 / 기록 1개 / 충분한 기록을 별도 상태로 구성한다. 빈 상태는 점수 0이나 실패로 표현하지 않는다.
10. 초기 화면의 빈 Box를 로고·캐릭터와 짧은 안내로 교체한다. 부가 네트워크 작업이 홈 진입을 계속 막지 않도록 초기화 의존성을 정리한다.

### 영향 코드

- App / AppRootViewModel / Auth 흐름
- SleepSettingsRepository / SleepRecordRepository / SleepSyncRepository
- StatsScreen / PremiumOverlay / 권한 요청기

### 완료 조건

- 신규 설치 후 로그인·구독 없이 기본 일정 설정, 잠금 시작, 기록 조회까지 가능하다.
- 필수 권한이 없는 경우 무엇이 안 되는지 명확하며 관련 없는 기능은 사용할 수 있다.
- 앱 종료·재실행 후 게스트 일정과 기록이 유지된다.
- 로그인·로그인 실패·계정 전환으로 로컬 기록이 유실되거나 다른 계정에 섞이지 않는다.
- 무료 기록 화면에 전체 차단 오버레이가 없고 기록 없음과 오류가 구분된다.

## 2단계: 2차 개편 — 취침과 잠금 경험 개선

### 작업

1. 홈을 오늘 적용 일정, 자동 예약 상태, 잠금 준비 상태, 시작 버튼 중심으로 재구성한다. 기기 오비트는 작은 기기 상태 카드로 축소한다.
2. 홈 주요 버튼은 준비 부족이면 준비하기, 준비 완료면 지금 시작, 처리 중이면 준비 중, 실행 중이면 실행 상태 확인으로 바뀐다.
3. 탭은 홈 / 기록 / 수면 일정 / 설정으로 정리한다. 설정의 중복 루틴 편집은 일정 화면으로 연결하며 평일·주말 선택 맥락을 유지한다.
4. 일정에 오늘만 변경을 추가한다. 30분 늦추기, 직접 지정, 오늘 예약 건너뛰기를 제공하고 원래 반복 루틴은 유지한다.
5. 일정 예외의 만료 시점과 날짜·자정 경계를 정의한다. 적용 전 실제 다음 시작·해제 시각을 보여준다. 앱 재실행에도 예외가 유지되어야 한다.
6. 취침 준비 알림에서 지금 시작 / 한 번 미루기를 제공한다. 미루기는 무한 반복을 기본으로 유도하지 않고 다음 예약을 명확히 표시한다.
7. 잠금 화면을 저자극 형태로 바꾼다. 자동 해제 시각과 남은 시간, 정적인 캐릭터, 허용 앱, 긴급 사용, 종료를 우선한다.
8. 일반 종료는 확인 절차와 접근성 대체 조작을 제공한다. 긴급 전화·긴급 사용은 지연·구독 제한 없이 제공한다.
9. 허용 앱의 판단과 오버레이 동작을 실제로 연결한다. 화면에 전화 버튼만 추가하고 오버레이가 그 앱을 다시 덮는 구현은 완료로 인정하지 않는다.
10. 예약 실행·기기 재시작·권한 변경·서비스 중단·시간대 변경 시 적용 상태를 복구하고 사용자에게 확인된 결과를 보여준다.
11. 취침·잠금·긴급 접근 경로의 광고를 제거한다. 일반 정보 화면의 광고도 핵심 동작을 방해하지 않게 운영한다.

### 완료 조건

- 홈에서 오늘 일정과 실행 가능 여부를 바로 읽고 탭으로 시작할 수 있다.
- 오늘만 변경이 다음 날 기본 루틴에 영향을 주지 않는다.
- 실제 허용 앱에 접근할 수 있으며 잠금이 해당 앱을 다시 막지 않는다.
- 긴급 사용이 즉시 가능하고 TalkBack으로 시작·종료·긴급 접근이 가능하다.
- 작은 화면·큰 글꼴에서 자동 해제 시각과 긴급 버튼이 잘리지 않는다.

## 3단계: 3차 개편 — 아침 결과와 기록 신뢰 확보

### 작업

1. 종료 후 다음 앱 방문 시 짧은 아침 결과를 제공한다. 화면을 강제로 켜거나 앱을 소환하지 않고 사용자가 확인할 때 자연스럽게 보여준다.
2. 시작·종료 시각, 유지 시간, 종료 유형, 목표 적용 정보를 보여준다. 실제 수면 시간과 다를 수 있음을 가까이에 설명한다.
3. 사용자의 선택으로 컨디션과 실제 취침 추정 시간을 입력하게 한다. 미입력도 허용하고 수동 입력과 시스템 기록을 구분한다.
4. 통계의 수면 점수·효율·부채를 취침 루틴 또는 목표 기반 지표로 정리한다. 정의와 계산 근거를 설명한다. 목표 변경이 과거 기록에 소급해 잘못 적용되지 않게 한다.
5. 한두 개 기록으로 추세를 단정하지 않는다. 비교 기간·표본 수를 표시하고 부족하면 더 기록이 필요하다고 안내한다.
6. 기록 없음은 0과 구분한다. 연속 기록은 단순 기록 존재와 목표 달성을 나눠 표시한다. 중도 종료도 실제 유지 시간은 보존한다.
7. 통계 첫 화면은 주요 지표 세 개, 주간 차트 하나, 실행 가능한 제안 하나로 줄인다. 상세 기록과 계산 기준은 별도 진입으로 제공한다.
8. 로컬 기록 저장을 먼저 완료한 뒤 서버 전송 대기를 관리한다. 실패 재시도, 중복 제거, 여러 기기 종료 이벤트의 단일 기록 처리를 구현한다.
9. 로딩은 최초 스켈레톤과 부분 새로고침으로 나눈다. 실패 시 캐시를 유지하며 마지막 갱신 시각과 전송 대기를 보여준다. 실제 저장 확인 전 안전하게 저장됐다고 말하지 않는다.
10. 다중 기기의 등록 / 연결 / 명령 전송 / 적용 확인을 구분한다. 일정 시간 응답이 없으면 확인되지 않음으로 표시하며 이미 성공한 기기의 잠금은 유지한다.
11. 기록 조회의 중복 실행과 진입마다 장기 범위를 다시 가져오는 흐름을 줄인다. 표시 기간부터 읽고 상세 범위는 요청 시 조회한다.
12. 설정의 버전·계정·구독·지원 행을 정리하고 행동이 없는 행의 화살표를 제거한다. 기록 삭제·계정 삭제 안내는 실제 삭제 범위와 일치하게 한다.

## 4단계: 이후 — 유료가 지속적으로 가치 있게 만들기

### 작업

1. 무료 기본 잠금·일정·긴급 접근·본인 기록·복구를 보장하는 기능 정책을 먼저 고정한다. 구독 만료 후에도 로컬 기본 루틴과 기록을 유지한다.
2. 자동 루틴: 요일별 준비 알림·잠금 시작·자동 해제와 복수 루틴을 제공한다. 루틴 충돌 시 적용 우선순위와 다음 이벤트를 설명한다.
3. 세밀한 차단 규칙: 선택 앱, 시간대, 루틴별 예외, 일반 해제 확인 강도를 제공한다. 긴급 접근과 종료 가능한 안전 경로는 항상 보장한다.
4. 다중 기기 잠금: 각 기기 상태 확인, 일부 실패 재시도, 기기별 규칙을 제공한다. 단순 등록 수 증가가 아니라 실제 적용 확인이 가치다.
5. 장기 비교: 시작 시각·유지 시간·목표 달성·중도 종료처럼 수집한 정보만으로 4주·월간 변화를 제시한다. 부족한 기록과 비교 불가 상태를 제공한다.
6. 개선 계획: 요일별 시작 지연에 따른 준비 알림 변경처럼 사용자가 바로 적용할 수 있는 한 가지 제안을 제공한다. 사용자가 수정·거절할 수 있고 이후 효과를 확인한다.
7. 콘텐츠는 자동화와 분석의 사용성이 안정된 뒤 확장한다. 기본 호흡 안내는 무료, 상황별 루틴·선택 오디오·오프라인 콘텐츠는 유료 후보로 둔다. 콘텐츠 권리와 운영 부담도 고려한다.
8. 구매 안내는 사용자 선택으로 확장 기능에 접근할 때 제공한다. 나중에·무료로 계속·구매 복원을 명확히 제공한다. 기본 기능을 사용하는 중간에 판매 화면으로 강제 이동시키지 않는다.
9. 상품 가격, 결제 주기, 체험 자격·기간, 갱신 조건을 실제 스토어 상품에서 표시한다. 계산하지 않은 할인율이나 고정 체험 일수를 넣지 않는다.
10. 결제 제출 / 사용자 취소 / 결제 대기 / 결제 확인 / 혜택 확인 지연 / 구매 복원 / 활성 / 만료를 구분한다. 결제 성공 여부가 불명확하면 다시 결제를 유도하지 않는다.
11. 혜택 확인이 끝나면 구매한 기능을 설정하는 화면으로 안내한다. 첫 자동 루틴 설정과 두 번째 기기 연결 중 하나를 선택하게 한다.
12. 구독 관리에 갱신 정보·구매 복원·해지 관리 진입을 제공한다. 구독 만료 후 고급 루틴의 처리와 기본 루틴 전환을 사전에 설명한다.

## 디자인 시안 검토 메모

생성 이미지의 문구·날짜·아이콘은 제안이며 구현 시 이 문서의 상태 정의를 기준으로 정리한다. 이미지와 문서가 충돌하면 확인된 기능과 상태 정의가 우선한다. 첫 사용 화면의 날짜·시간 예시는 사용자 환경의 실제 값으로 치환한다. 각 단계의 시안은 대표 상태를 보여주며 위 상태 목록을 모두 이미지로 표현한 것은 아니다.
