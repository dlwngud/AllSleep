# AllSleep 제품 개편 구현 로드맵 v2

기준일 2026년 10월 13일 · 총 21단계 · Android 우선

이 로드맵은 새 AGENTS.md의 UX 우선, 단순한 구조, 빠른 가설 검증 원칙을 적용한 구현 계획이다. 기존 29단계 계획을 대체한다. 제품 기획과 67개 화면의 최종 범위는 유지하면서, 실제로 사용할 수 있는 기능 단위로 작업을 묶고 무료 경험과 첫 유료 검증의 완료 지점을 앞당긴다.

이번 작업은 계획 재작성이다. 앱 구현 단계가 실행되거나 네이티브 테스트가 통과한 것으로 표시하지 않는다. 이전 계획과 진행표는 planning-history/2026-10-12-v1/에 보존했다. 단계 요청에서는 V2-01처럼 버전이 포함된 번호를 사용한다.

## 1. 작업의 기준

- 기존 단일 composeApp 모듈, Compose Multiplatform, Koin, Navigation Compose 2와 Firebase를 우선 활용한다. 프로젝트 전체의 모듈화·DI 교체·내비게이션 교체를 선행 작업으로 만들지 않는다.
- 공통 컴포넌트와 모델은 실제 기능에 필요한 만큼 만든다. 모든 미래 데이터 모델과 기능을 미리 설계하는 작업을 별도 단계로 두지 않는다.
- 한 기기의 설정·제한·해제·기록부터 완성하고, 그 경험을 확인한 뒤 계정·여러 기기·결제를 연결한다.
- 여러 기기 제한을 첫 Plus 가치로 검증한다. 복수 루틴과 고급 비교는 이어서 구현한다. 미구현 기능은 판매 혜택에 표시하지 않는다.
- 첫 파일럿에 필요한 최소 계측은 무료 경험 직후 넣는다. 큰 분석 플랫폼이나 운영 대시보드를 먼저 만들지 않는다.
- 공통 테스트는 kotlin.test와 kotlinx-coroutines-test, 외부 경계는 Fake Repository·DataSource를 사용한다. 실제 문제 없이 새 테스트 도구를 추가하지 않는다.
- 테스트 커버리지 수치 대신 중요한 상태·시간·데이터 보존·예외 접근을 검증한다. 실제 앱 제한과 해제, 권한·예약·구매는 필요한 기기에서 확인한다.
- 각 단계에서 변경한 구조·명령·제품 규칙을 AGENTS.md와 해당 명세에 반영한다. 지침을 나중에 한 번 작성하는 별도 단계는 두지 않는다.

## 2. 제품 완료 지점

| 완료 지점 | 단계 | 가능한 결과 |
| --- | --- | --- |
| 첫 설정과 실제 실행 | V2-07 | 로그인 없이 약속을 만들고 이 기기에서 제한 시작 |
| 무료 핵심 경험 | V2-10 | 한 기기의 설정·야간 예외·예정 해제·아침 기록 |
| 첫 행동 가설 검증 준비 | V2-11 | 내부 테스트 후보와 최소 지표, 파일럿 실행 계획 |
| 첫 유료 경험 검증 준비 | V2-16 | 지원 기기 연동을 실제 혜택으로 구매·복원·해지·무료 복귀 |
| 전체 Android 개편 | V2-19 | 추가 루틴·비교·조정까지 구현하고 출시 수준 검증 |
| iOS 확장 선택 | V2-20~21 | 확인된 지원 범위 안에서 iOS와 교차 기기 기능 |

첫 실행이 가능한 것과 외부 사용자에게 배포할 준비가 된 것은 다르다. 파일럿과 판매는 그 시점에 완성된 기능, 데이터 처리 안내, 실제 기기·스토어 검증 범위에 맞춰 진행한다. 공개 배포나 외부 메시지 전송은 해당 행동에 대한 사용자 지시 범위에서 수행한다.

## 3. 단계별 구현 계획

### V2-01 현재 상태와 첫 구현 기준 확인

**사용자 결과:** 기존 변경과 데이터를 보존하면서 개편의 출발점을 확인한다.

**선행 조건:** 기획서·시안·AGENTS.md 준비.

**작업:**

1. 현재 브랜치·미커밋 변경·작업 공간·기존 구독자와 데이터의 보존 범위를 확인한다. 사용자가 삭제하거나 수정한 파일을 임의로 복원하지 않는다.
2. 기존 빌드와 verify.sh를 실행해 현재 실패를 파악한다. Android 실기기에서 기존 제한·해제·권한의 핵심 경로를 확인한다.
3. 로그인 강제 이동, Firestore 중심 기록, 시스템 앱 여부 중심 제한 정책과 서비스의 계정 의존을 다시 확인한다.
4. 첫 구현에 필요한 선택만 확정한다. 기본 루틴, 로컬 저장, 실행 확인, 긴급 접근과 기존 기록 이관의 기준을 짧게 기록한다.

**완료 기준:** 실제 기준 상태와 기존 실패·보존 대상·첫 구현 결정이 확인되었다. 복잡한 전체 시스템 설계나 긴 기술 보고서가 완료 조건은 아니다.

**검증:** 기준 빌드·단위 테스트와 가능한 실제 기기 확인. 없는 기기나 외부 설정은 필요한 조건으로 기록한다.

### V2-02 광고 제거와 공통 화면 기반

**사용자 결과:** 광고가 취침 경험을 방해하지 않으며 새 화면을 일관된 모양으로 만들 수 있다.

**선행 조건:** V2-01.

**작업:**

1. 앱 오픈 광고 코드·SDK·주입·매니페스트·필수 광고 설정을 함께 정리한다.
2. 네이비·보라색·캐릭터를 유지하고 필요한 색상·글자·여백·버튼 토큰을 정한다.
3. 오늘·루틴·기록·마이 탭과 공통 버튼·설정 행·입력·상태 안내를 만든다. 컴포넌트는 이후 실제 화면을 만들면서 확장한다.
4. 시스템 영역·키보드·작은 화면·큰 글꼴 대응의 기본 구조를 마련한다. 필요한 테스트 환경만 보완한다.

**관련 화면:** 전체 공통 구성과 네 개 탭.

**완료 기준:** 광고 설정 없이 앱을 빌드할 수 있고 대표 화면의 공통 구성과 탭이 실제 앱에서 동작한다.

**검증:** 컴파일·린트·관련 테스트, 대표 화면 렌더링과 버튼·시스템 영역 확인.

### V2-03 로그인 없는 로컬 사용과 기록 기반

**사용자 결과:** 로그인과 인터넷 연결 없이 설정과 진행 상태가 유지된다.

**선행 조건:** V2-01~02.

**작업:**

1. 게스트의 앱 진입과 홈·루틴 접근을 구현해 로그인 강제 이동을 분리한다.
2. 지금 필요한 루틴·취침 회차·세션·로컬 소유자·원본 기록의 최소 모델을 만든다. 계정·원격 기기·구독 세부 계약은 해당 단계에서 확장한다.
3. 자정 이후 해제, 고유 세션 ID, 요청·실행 확인·종료·해제 확인·중단을 표현한다.
4. 실제 저장과 재읽기를 구현한다. 설정은 기존 DataStore를 우선 활용하며 기록 저장은 영속성·원자적 갱신·조회 요구에 맞는 최소 방식을 선택한다. 새 데이터베이스가 필요하면 이유를 기록한다.
5. 기존 설정과 기록을 보존한다. 이전 기록에 없는 실행 확인이나 임시 사용 정보를 추정해 넣지 않는다. 계정별 클라우드 이관은 V2-12에서 완성한다.

**관련 화면:** 게스트 진입, H01~H02·S03의 기반.

**완료 기준:** 앱 종료·재실행 뒤에도 설정과 세션 상태가 남고 같은 밤의 여러 기록이 덮어쓰이지 않는다. 계정·서비스 조회 실패가 로컬 진입을 막지 않는다.

**검증:** 날짜 경계·상태 전환·중복 저장·쓰기 실패·재시작·기존 설정 이관. 공통 테스트와 실제 저장 확인을 구분한다.

### V2-04 선택 앱 제한과 필수 앱 접근

**사용자 결과:** 선택한 앱만 실제로 제한되고 전화와 필요한 앱은 접근할 수 있다.

**선행 조건:** V2-03.

**작업:**

1. 실제 설치 앱 목록·검색·선택·항상 허용 목록을 구현한다. 허용과 제한이 겹치면 허용 우선 결과를 안내한다.
2. 기존 접근성 서비스·전경 서비스·오버레이를 로컬 세션과 연결한다. 시스템 앱 전체 허용 규칙은 실제 필요한 예외로 정리한다.
3. 시작·해제 요청과 OS 실행 확인을 구분한다. 중복 명령과 늦은 시작 응답이 종료를 덮지 않도록 처리한다.
4. 기본 즉시 해제와 예정 해제 경로를 유지하고 계정·네트워크 의존을 제거한다.
5. 서비스 중단·권한 철회·앱 설치 및 삭제를 처리한다. OS 제약은 실제 대상 버전과 기기로 확인한다.

**관련 화면:** O04, R03, H06·N01·X02의 실행 기반.

**완료 기준:** 선택 목록과 실제 제한 대상이 일치하며 허용 앱을 다시 가로막지 않는다. 서비스 호출만으로 성공을 표시하지 않는다.

**검증:** 실제 앱 전환·전화·인증 앱·선택 없음·허용 충돌·중복 시작·빠른 종료·서비스 중단·오프라인 해제.

### V2-05 권한 준비와 실제 10초 테스트

**사용자 결과:** 왜 허용이 필요한지 이해하고 제한·해제의 작동 여부를 먼저 확인한다.

**선행 조건:** V2-04.

**작업:**

1. 접근성·오버레이·알림·예약 관련 허용의 목적과 필요 수준을 구분한다.
2. 실제 정보 처리 범위에 맞춘 접근성 별도 고지와 명시적 동의를 제공한다.
3. 시스템 설정에서 돌아오면 실제 권한과 서비스 상태를 다시 확인한다.
4. 10초 테스트의 제한과 자동 해제를 확인한다. 테스트 회차와 실제 취침 기록을 분리한다.
5. 거절·나중에 준비·테스트 시작 실패·해제 미확인을 처리한다.

**관련 화면:** O05~O08, H02, X02.

**완료 기준:** 시작과 해제를 모두 확인한 경우만 준비 완료이며 설정 복귀만으로 사용자가 요청하지 않은 제한이 시작되지 않는다.

**검증:** 허용·거절·복귀·테스트 중 앱 종료·해제 실패·접근성 읽기 순서와 긴급 경로.

### V2-06 평일과 주말 루틴 및 자동 예약

**사용자 결과:** 한 번 정한 취침 약속이 해당 요일에 반복된다.

**선행 조건:** V2-03~05.

**작업:**

1. 무료 기본 루틴 한 세트 안에 평일·주말 시각·요일·활성화 값을 구현한다.
2. 실제 다음 시작 날짜와 다음 해제 시각을 보여주고 Android 예약과 연결한다.
3. 예약 등록과 실제 제한 실행 확인을 분리한다. 자동 시작 미확인 시 직접 시작 경로를 제공한다.
4. 재시작·시간 및 시간대 변경·예약 권한 변경에 따른 갱신을 처리한다.
5. 제한 해제 시각과 선택적인 소리 기상 알람을 구분한다.

**관련 화면:** R01~R02의 기본 루틴, H01의 다음 일정.

**완료 기준:** 저장한 평일·주말 일정과 실제 예약이 일치하며 실패한 예약을 준비 완료로 표시하지 않는다.

**검증:** 자정 넘김·같은 시각 입력·요일·활성화 조합·기기 재시작·실제 예약 시작 및 해제.

### V2-07 온보딩과 오늘 화면 연결

**사용자 결과:** 로그인·결제 없이 약속 설정부터 이 기기의 제한 시작까지 진행한다.

**선행 조건:** V2-02~06.

**작업:**

1. 가치 소개·선택 원인 질문·시각·앱 선택·권한·테스트·준비 완료를 실제 기능과 연결한다.
2. 중간 앱 종료 후 저장한 선택과 적절한 단계로 복귀한다.
3. 오늘의 시각·대상 앱·예약·준비 상태를 표시하고 상태에 맞는 주 행동을 제공한다.
4. 처리 중 반복 탭·확인 지연·실행 중 복귀·준비 필요 상태를 구현한다.
5. 게스트 마이에서는 기본 설정과 로그인·백업의 이유를 안내한다. 계정 관리는 V2-13에서 완성한다.

**관련 화면:** O01~O09, H01~H02·H06, S03의 첫 사용, M01의 게스트 안내.

**완료 기준:** 시안의 완료 상태를 보기 위한 버튼 대신 실제 결과를 관찰한다. 신규 설치 후 로그인 없이 설정과 실제 제한 시작을 완료한다.

**검증:** 신규 설치 전체 흐름·질문 건너뛰기·권한 나중에·테스트 실패·재실행·시작 요청 중복.

### V2-08 야간 화면과 필요한 예외 접근

**사용자 결과:** 취침 중에는 조용한 화면을 보고, 필요한 앱과 긴급 기능을 사용할 수 있다.

**선행 조건:** V2-04~07.

**작업:**

1. 제한 중 해제 시각·실제 상태·허용 앱을 표시하고 일반 탭과 닫기를 숨긴다.
