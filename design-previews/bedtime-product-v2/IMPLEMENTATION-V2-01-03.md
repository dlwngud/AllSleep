# AllSleep V2-01~03 구현·검증 기록

2026년 10월 13일 · Android 우선 · 작업 공간: `/Users/wngud/Workspace/AllSleep` · 기존 `develop` 브랜치

**1~3단계의 화면·로컬 데이터 기반을 구현하고 검증했다.** 로그인 없이 네 탭에 진입하고 평일·주말 시각을 저장할 수 있다. 새 로컬 세션의 실제 앱 제한·권한·자동 예약 연결은 V2-04~06에 남아 있다. 93개 전체 시안이나 무료 핵심 경험이 완성된 상태는 아니다.

## V2-01: 출발점과 보존 기준

- 수정 전 소스와 변경 목록을 별도로 보존하고 기존 `verify.sh`의 컴파일·린트·단위 테스트 통과를 확인했다. 기존 사용자 변경을 초기화하거나 삭제된 `agent.md`를 복원하지 않았다.
- 기존 로그인 강제 이동, 계정·Firestore 중심 서비스와 기록, 시스템 앱 전체 허용 정책을 확인했다. 개편은 기존 단일 모듈·Koin·Navigation Compose 2를 유지한다.
- 연결된 Galaxy S20(Android 13/API 33)의 설치 앱과 권한·서비스 상태를 확인했다. 기준 확인 당시 실행 중인 제한 서비스는 없었다. 기존 설치 APK와 로컬 설정을 작업 전 별도 보관했다.
- 디버그 업데이트 설치로 앱 데이터를 보존했다. 기존 결제 구현, 계정·구독 화면, 홈 화면 원본과 사용자가 수정한 아이콘을 보존했다. 서버 데이터나 구독을 삭제·변경하는 이관을 실행하지 않았다.
- 기존 제한의 시작·해제와 전화 접근을 실기기에서 재현하지 않았다. 해당 기능은 선택 앱 정책과 로컬 실행을 연결하는 V2-04의 필수 검증으로 남긴다.

## V2-02: 광고 제거와 네 탭

- 앱 오픈 광고 SDK·관리자·DI·초기화·매니페스트 설정·필수 광고 키 검사를 함께 제거했다. 광고 대기 때문에 시작 화면에 머무는 흐름도 제거했다.
- 네이비·보라색·기존 캐릭터를 유지하고 타이포그래피, 카드, 버튼, 입력, 상태 안내와 설정 행을 추가했다. 실기기 확인 후 카드 글자·입력 포커스의 대비와 하단 탭 간격을 조정했다.
- 하나의 `NavHost`와 공통 `Scaffold`에서 **오늘 → 루틴 → 기록 → 마이** 네 탭이 동작한다. 로그인은 마이에서 선택하며 기존 계정·구독 관리는 로그인한 사용자의 별도 경로로 유지한다.
- 세로 스크롤, 시스템 영역 여백과 입력 중 스크롤을 적용했다. 360dp 폭·글꼴 2배 환경의 편집 동작을 확인했다.

## V2-03: 로컬 사용과 기록

- 앱 진입은 로컬 초기화만 기다린다. 계정 조회가 끝나지 않거나 실패해도 기본 탭을 사용할 수 있다. 늦게 도착한 계정 조회가 관찰된 로그아웃 상태를 덮는 경우도 방지했다.
- 평일·주말 시각과 활성화 값을 로컬에 원자적으로 저장한다. 기존 기본값인 평일 `23:00 → 07:00`, 주말 `00:00 → 09:00`을 유지했다. 기존 잘못된 시각은 임의 수정하지 않고 편집으로 복구할 수 있다.
- 루틴·회차·세션·로컬 소유자·원본 기록의 최소 모델을 만들었다. 시작 요청/실행 확인/해제 요청/해제 확인/기술 중단을 구분한다. 자정과 시간대 경계, 중복·늦은 확인과 동일 밤 복수 기록을 처리한다.
- 소유자는 최초 한 번 UUID로 만든다. 세션 ID는 생성자가 고유하게 만들고 재시도에 재사용한다. 같은 ID의 재시도는 종료한 기록을 되살리지 않으며 다른 소유자의 기록을 수정할 수 없다.
- 확인된 닫힌 실행 구간만 완료 시간으로 계산한다. 제한 기록을 실제 수면 시간·수면의 질로 표현하지 않는다.
- **기존 하나의 DataStore Preferences + 버전 JSON**을 선택했다. 작은 로컬 기록과 설정을 같은 트랜잭션으로 유지하는 현재 요구에 충분하며 별도 DB를 선행 도입하지 않았다. 기록은 전체 문서를 갱신하므로, 실제 데이터 규모·부분 조회 요구가 늘면 Room 등 저장 방식을 다시 판단한다.
- 잘못된 JSON·미지원 버전·쓰기 실패·취소에서 원본을 보존한다. 설정 초기화도 기록과 소유자를 삭제하지 않는다. 소유자가 불명확한 이전 활성 시각은 확인된 실행으로 만들지 않는다.
- 로그인만으로 게스트 기록을 계정에 병합하지 않는다. 기존 Firestore 기록의 계정별 이관·백업은 V2-12에서 구현한다.

## 재현 방법

저장소 루트에서 `./verify.sh`로 기본 검증한다. `./gradlew :composeApp:assembleDebug :composeApp:assembleDebugAndroidTest`로 앱과 테스트 APK를 만든다. 전용 테스트 기기에서는 `connectedDebugAndroidTest`를 사용할 수 있다. 이번 개인 기기 검증은 기존 앱을 삭제하지 않는 다음 방식으로 수행했다.

```sh
adb install -r -t composeApp/build/outputs/apk/debug/composeApp-debug.apk
adb install -r -t composeApp/build/outputs/apk/androidTest/debug/composeApp-debug-androidTest.apk
adb shell am instrument -w -r -e class com.wngud.allsleep.ui.bedtime.BedtimeFoundationUiTest com.wngud.allsleep.test/androidx.test.runner.AndroidJUnitRunner
```

명령 종료 코드만 보지 않고 `OK (4 tests)`를 확인한다. 실제 앱 프로세스 재실행은 활성 제한이 없는 상태에서만 수행했다.
